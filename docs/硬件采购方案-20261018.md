# 儿童陪伴 Agent 硬件采购方案（2026-10-18）

> 用途：5–6 岁儿童语音陪伴终端（thin client：麦克风 + 喇叭 + 联网 + 电池），服务端跑在自家 VPS。
> 价格为 2026-10 淘宝/京东大致参考价，下单前以实时价为准。

## 一、别人怎么做电池优化（对标研究）

| 产品 | 电池/续航（公开数据） | 省电核心做法 |
|---|---|---|
| 小天才电话手表 Q3A/Z12 | 760–780mAh；正常使用 1–2 天，待机约 7 天；磁吸充电，充满约 100 分钟 | 按键/抬腕唤醒（非语音常开）；定位按间隔上报；视频通话最耗电——**耗电功能按需开** |
| 火火兔故事机 G6 | 3.7V 800mAh（2.96Wh）；4Ω/3W 喇叭 | **本地 TF 卡离线播放，不联网**——这是故事机续航长的根本原因；按键操作 |
| 牛听听读书牛 | WiFi 熏教机，Type-C 充电 | 下载后离线熏听 + 定时关机；联网只在同步内容时 |
| 点读笔类（小熊等） | 锂电池，连续播放约 6 小时 | **闲置 3 分钟自动关机**；低电量红灯 + 30 秒后自动关机；2–3 个月不用的话要补电防过放 |
| 小度/小爱智能音箱 | 无电池，**常通电** | always-on 语音唤醒的代价就是插电——便携版极少，这是行业用脚投票的结果 |
| 行业唤醒芯片 | Syntiant NDP100：唤醒识别时 <150µW；唯创 WT2606A：双核 DSP 本地唤醒 | 真·超低功耗唤醒靠**专用神经网络芯片**，不是靠主 CPU 空转 |

**结论（四条铁律）：**
1. **便携儿童设备没有一家做"语音常开唤醒"**——全是按键/触摸唤醒 + 睡眠。语音唤醒只出现在插电设备上。
2. **离线是省电之王**：火火兔/牛听听把内容放本地，续航直接翻倍。我们的音频缓存策略（VPS + 终端本地）与此同构。
3. **闲置自动睡**：3 分钟无交互进 deep sleep 是行业标准动作。
4. **耗电排序**：喇叭播放 > WiFi 传输 > CPU > 麦克风待机。优化先砍大头：限音量、音频压缩（Opus）、WiFi 按需建连。

**续航估算（2000mAh）：**
- 日用模型：每天对话 30 分钟（active 约 350mA → 175mAh）+ 23.5h deep sleep（约 0.2mA → 5mAh）≈ 180mAh/天 → **约 11 天一充**
- 若开 ESP-Skainet 语音唤醒常驻（约 40mA）：24h = 960mAh → **约 2 天**——这就是不推荐常开唤醒的原因
- 充电：2.5 小时充满；低电量语音提醒"该充电啦"

### 方案 B（成品）：乐鑫 ESP32-S3-BOX-3 AI 语音开发套件

- 价格：约 ¥330–380（乐鑫官方淘宝店，现货）
- 配置：ESP32-S3 + 双麦 + 喇叭 + 触摸屏（可显示表情/歌词）+ 官方 ESP-Skainet 例程
- 优点：开箱即用，不用焊接；屏幕可做"情绪表情"，孩子喜欢
- 缺点：贵一倍；体积大（盒子形态）；电池需另配（无内置电池，Type-C 供电）
- 结论：**备选**——想最快验证选它；量产/定型走方案 A

### 不推荐的路线

- **树莓派 Zero 2 W**：$15 官价但**全球缺货数月**（2026-09 实查），且 idle 功耗 100mA+、无真 deep sleep，不适合电池设备
- **小爱音箱 Play（¥70）/小度音箱改造**：生态封闭，刷机改系统难度大，语音数据必经小米/百度云——**违反"语音数据默认不出内网"口径**，直接出局
- **Syntiant NDP + 定制 PCB**：功耗最优（<150µW 唤醒）但需画板打样，周期 1 个月+，留作二代优化项

## 三、系统架构（文字图）

```
[孩子] ⇄ (说话/听)
  ┌─ 终端 thin client ─────────────────────────┐
  │ 按键唤醒 → ESP32-S3 → INMP441×2 录音         │
  │   → Opus 压缩 → WiFi → VPS                  │
  │   ← MP3/Opus ← 本地缓存（断网可播）          │
  │   → MAX98357A → 喇叭播放                    │
  │ 电源：2000mAh + TP4056；3分钟无交互 deep sleep │
  └─────────────────────────────────────────────┘
                    ↕ WiFi (HTTPS/MQTT)
  ┌─ 自家 VPS ──────────────────────────────────┐
  │ nginx → voice-app → sherpa-onnx ASR         │
  │       → strategy → LLM → edge-tts → 音频流   │
  │ /data/child-audio 音频缓存                   │
  └─────────────────────────────────────────────┘
```

设计要点：
1. 终端只做**采集 + 播放 + 缓存**，识别/对话/合成全在 VPS（口径 A：数据不出自家服务器）
2. 音频 Opus 压缩后传输，带宽省 70%，WiFi 发射时间短 = 省电
3. 睡前故事等高频内容缓存在终端 Flash（16MB 可存约 2 小时 Opus 音频），断网可播

## 四、电池优化策略（落地清单）

1. **唤醒**：按键唤醒为主；预留 ESP-Skainet 语音唤醒固件开关，仅插电底座场景启用
2. **睡眠**：无交互 3 分钟 → 关 WiFi → deep sleep（目标 <100µA）；按键/RTC GPIO 唤醒
3. **联网**：WiFi 按需建连，对话结束即断；不用 MQTT 长连接（心跳是隐形耗电）
4. **播放**：优先播本地缓存；音量软件限 85dB（护耳 + 省电双收）
5. **充电**：Type-C + TP4056；低电量 20%/10% 两档语音提醒；长期不用每月补一次电（防过放）
6. **儿童安全**：电池仓螺丝固定；外壳圆角；无小零件脱落风险

## 五、组装步骤概要

1. **接线**（杜邦线，免焊接版）：INMP441×2 → ESP32-S3 I2S 引脚；MAX98357A → 同一 I2S 总线；喇叭 → 功放输出；电池 → TP4056 → 开发板 5V/Vin；按键 → GPIO0
2. **烧固件**：ESP-IDF + ESP-Skainet 唤醒词例程打底；音频采集推流对接 VPS `/api/talk`（复用现有 voice-app 接口）
3. **联调**：手机热点配网 → 按键唤醒 → 说话 → VPS 返回 → 喇叭播放，全链路跑通
4. **功耗实测**：万用表/功耗计测 deep sleep 电流与播放电流，校准续航估算
5. **装壳**：电池固定（泡沫胶 + 螺丝仓），喇叭开孔，麦克风开孔对准
6. **孩子实测**：P0b 30 句题库在硬件上跑一遍
