# 部门职责定义 v1.0（2026-10-16）

> 董事长令：各部门职责边界清晰，越界即违规。

## 董事长
- **职责**：定需求、定方向、最终拍板
- **边界**：不介入执行细节；不直接指挥工人
- **输入**：验收结果、重大决策事项

## CEO（Twt2026）
- **职责**：定方向、派单、验收、版本管理、PM backlog
- **边界**：不亲自干执行活（"别人不行你就自己干"为例外）；不点名具体工人（OpenClaw 选）；只管管理决策，不管技术细节
- **汇报**：向董事长主动汇报实质进展

## OpenClaw（运营总管兼项目经理）
- **职责**：唯一调度入口；任务分发、进度跟踪、工人协调、工人健康管理
- **边界**：不制定需求；不跳过 CEO 接董事长直派（董事长直派除外）
- **当前状态**：Bash 调度器代行，原生智能调度未完成

## Noesis（账号总管）
- **职责**：16 站点凭据托管；账号类任务执行；免费 key 获取（Groq/智谱/OpenRouter）
- **边界**：不管业务需求；凭据绝不写明文
- **状态**：2026-10-15 起失联，急事需董事长直接联系

## 技术部（Pi Agent / Claude Code / 光头）
- **职责**：写代码、执行、交付；开发→测试→验收闭环
- **边界**：按任务描述交付，不自行发挥；不直接对接董事长；需求变更走 CEO
- **状态**：光头停工（额度用完）；Claude Code 不可靠；Pi Agent 部分可用

## 外脑团（ChatGPT / Claude / Gemini）
- **职责**：重要方案多轮评审（发散→红队→事实核查）
- **边界**：只评审不执行；评审记录存档

## 跨部门铁律
1. 需求变更一律走 CEO，技术部不私自改需求
2. 派单只发 OpenClaw，CEO 不点名工人
3. 验收以真实产物为准，不以状态标记为准
4. 凭据/红线（Google/LINUX DO/X）全员遵守
