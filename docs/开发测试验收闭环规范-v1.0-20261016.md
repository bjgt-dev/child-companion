# 技术部开发→测试→验收闭环规范 v1.0（2026-10-16）

> 董事长令：所有技术任务必须走完开发→测试→验收闭环，缺一不可。

## 闭环三段

### 1. 开发（DEV）
- 按任务描述交付代码/文档/配置
- 代码修改先提交再部署（git commit，message 带任务 id）

### 2. 测试（TEST）
- 每个验收标准必须有**运行证据**：命令 + 实际输出
- 测试证据写入 result_file，不接受"我跑过了"口头报告
- 反例：opt-004 只写"开始调研"就标完成 → 打回

### 3. 验收（ACCEPT）
- 对照任务验收标准逐条打勾 ✅/❌
- 有产物：文件存在 + 内容符合要求（抽查）
- 无真实产物 = 未完成，不以"已派单""已完成"状态为准

## 打回规则
- 无测试证据 → 打回重做
- 产物不存在/内容不符 → 打回重做
- 连续 2 次打回 → 升级 CEO 亲自处理或换方案

## 任务模板（派单必须含）
- 背景、任务、验收标准（可量化）
- 工具契约
- result_file 路径
- 铁律（凭据/红线）
