# xiaozhi-esp32 深度研究报告

**日期**：2026-10-17
**目的**：儿童 AI 成长伙伴（5-6 岁）硬件载体选型 + 自建服务器技术评估
**信息源**：GitHub 官方仓库源码与文档（一手源），部分价格/规格来自厂商公开页面

---

## 一、结论先行

1. **自建服务器可行**：xinnan-tech/xiaozhi-esp32-server（Python，MIT，10.8k star）可完全替代官方 xiaozhi.me，ASR/LLM/TTS 全部可插拔，**我们的儿童教学策略引擎 + omemo 对话记忆可以接进去**。
2. **硬件推荐 ESP32-S3-BOX-3（¥299）**：室内场景首选。屏幕大（2.4 寸）、双麦克风、扬声器够响、资料最全。缺点：无电池，必须插 USB。
3. **户外备选 M5Stack CoreS3（约 ¥389）**：有电池版、带摄像头、可穿戴扩展。贵约 ¥90。
4. **唤醒词可自定义**：ESP-SR 离线唤醒，支持自定义唤醒词，孩子起的名字可以做唤醒词（需重新编译固件烧入模型）。
5. **延迟**：官方流式配置声称比基础版快约 2.5 秒；儿童场景要求 5 秒内回复，**待实测**（服务器自带 performance_tester.py 可测）。
6. **儿童内容安全是空白**：固件和服务器均无家长控制、无内容过滤。官方服务器是通用 LLM，无儿童特化。**必须我们自己在服务端加 system prompt 约束 + 敏感词过滤**。

## 二、系统架构

```
┌─────────────────┐         WebSocket / MQTT+UDP          ┌──────────────────────┐
│  ESP32-S3 设备   │◄────────────────────────────────────►│  自建 Python 服务器   │
│                  │   Opus 音频流 + JSON 控制消息          │                      │
│ - ESP-SR 离线唤醒 │                                      │ - ASR（FunASR本地/    │
│ - Opus 编解码    │         JSON-RPC 2.0 (MCP)            │   讯飞流式API）       │
│ - 表情屏/LCD     │◄────────────────────────────────────►│ - LLM（OpenAI兼容     │
│ - 设备端 MCP     │   工具发现 tools/list / 调用           │   接口，任意模型）   │
│   (音量/灯/GPIO) │   tools/call                          │ - TTS（EdgeTTS免费/   │
└─────────────────┘                                      │   火山流式）         │
                                                         │ - 记忆（mem_local/    │
                                                         │   mem0ai）           │
                                                         │ - 声纹/意图/知识库   │
                                                         └──────────────────────┘
```

设备端只做三件事：离线唤醒词检测、回声消除、Opus 编解码。ASR/LLM/TTS 全在服务器。

## 三、通信协议详解

### 3.1 WebSocket 协议（推荐自建时用，防火墙友好）

**握手流程**：
1. 设备唤醒/按键 → `OpenAudioChannel()` → 建 WebSocket 连接
2. 请求头：`Authorization: Bearer <token>`、`Protocol-Version`、`Device-Id`（MAC）、`Client-Id`（UUID）
3. 设备发 `hello`：含 `version`、`features{mcp:true}`、`transport:"websocket"`、`audio_params{format:opus, sample_rate:16000, channels:1, frame_duration:60}`
4. 服务器回 `hello`：含 `transport:"websocket"`、`session_id`（可选）、`audio_params{sample_rate:24000}`（下行用 24kHz 音质更好）
5. 10 秒内无正确回复 → 判连接失败

**消息类型**（JSON 文本帧 + Opus 二进制帧混传）：

| 方向 | type | 说明 |
|------|------|------|
| 设备→服务器 | hello | 握手 |
| 设备→服务器 | listen | state: start/stop/detect（detect=唤醒词触发），mode: auto/manual/realtime |
| 设备→服务器 | abort | 打断 TTS，reason 可为 wake_word_detected |
| 设备→服务器 | mcp | JSON-RPC 2.0 载荷，设备上报工具执行结果 |
| 服务器→设备 | stt | 语音识别文本 |
| 服务器→设备 | llm | emotion 字段驱动表情动画 |
| 服务器→设备 | tts | state: start/stop/sentence_start（sentence_start 带文本可显示字幕） |
| 服务器→设备 | mcp | tools/call 下发设备控制指令 |
| 服务器→设备 | system | command: reboot（远程重启/OTA 相关） |
| 双向 | custom | 自定义消息（需编译开关） |
| 双向 | 二进制帧 | Opus 音频 |

**二进制协议**有三个版本：v1 直接发 Opus；v2 带时间戳头（供服务端 AEC）；v3 精简头。

**状态机**：Idle → Connecting → Listening → Speaking → Idle；异常/打断可从任何态回 Idle。

### 3.2 MQTT + UDP 协议（实时性更高，部署复杂）

- **MQTT**：控制通道（hello/listen/tts/mcp 等 JSON 消息），支持 TLS（8883）
- **UDP**：音频通道，AES-CTR 加密，包结构 `type(1B)|flags(1B)|len(2B)|ssrc(4B)|timestamp(4B)|seq(4B)|payload`
- 密钥通过 MQTT hello 响应下发（key + nonce，128 位）
- 序列号防重放、防乱序
- 官方对比：MQTT+UDP 实时性高、防火墙友好度低、复杂度高；WebSocket 反之

**自建建议**：先用 WebSocket，部署简单、穿透性好；延迟不达标再切 MQTT+UDP。

## 四、自建服务器评估（xinnan-tech/xiaozhi-esp32-server）

### 4.1 基本情况
- MIT 协议，10.8k star，3.8k commit，77 个 release，华南理工刘思源团队主导
- Docker 一键部署；最简配置 2 核 2G（全 API 模式），FunASR 本地模式需 2 核 4G
- 同时支持 WebSocket 和 MQTT+UDP、MCP 接入点、声纹识别、知识库、Web 智控台

### 4.2 组件插拔（全部可换）

| 组件 | 免费方案 | 流式/高性能方案 | 说明 |
|------|----------|----------------|------|
| ASR | FunASR（本地）/ SherpaASR | 讯飞流式 ASR | 任何兼容接口可接 |
| LLM | 智谱 glm-4-flash（免费） | 通义 qwen-flash | **任何 OpenAI 兼容接口** |
| TTS | EdgeTTS（微软免费） | 火山双流式 TTS | 本地 FishSpeech/GPT-SoVITS 也支持 |
| VAD | SileroVAD（本地免费） | — | — |
| 记忆 | mem_local_short（本地） | mem0ai / PowerMem | **可替换为我们的 omemo** |
| 意图 | function_call | intent_llm | 插件化 |

### 4.3 接入我们现有系统的改造点

1. **LLM 层**：服务器 LLM 配置指向我们的代理（带儿童教学策略的 system prompt + 策略引擎）。因服务器支持任意 OpenAI 兼容接口，**只需改配置 URL，无需改服务器代码**。
2. **记忆层**：服务器自带 mem_local_short / mem0ai；我们的 omemo 已跑在 localhost:8100 且兼容 OpenAI 接口，**可直接替换 Memory 组件配置**。
3. **成长事件**：服务器无 xAPI/成长事件概念。需在服务器的对话回调处加 hook，把每轮对话记入我们的 `growth_event.py`（学习事件表）。**约 50-100 行新增代码**。
4. **内容安全**：服务器无儿童过滤。需加两层：① system prompt 约束（已有儿童教育宪章 v2.0 可用）；② 敏感词/话题过滤中间件（新增）。
5. **声纹识别**：服务器支持 3D-Speaker 声纹，可用于区分孩子和家长的声音——对"家长模式/儿童模式"切换有用。

### 4.4 风险
- 官方警告：功能未完善、未过网络安全测评，**勿直接用于生产环境**；公网部署需自行加固
- 个人数据（儿童语音）过自建服务器：需注意数据合规，**建议只部署在家庭内网或自有 VPS，不走公网**

## 五、MCP 协议（设备控制）

### 5.1 设备端 MCP（MCP Server 跑在 ESP32 上）
- 后台（MCP Client）→ 设备：`initialize` → `tools/list` → `tools/call`
- 设备用 `McpServer::AddTool(name, description, properties, callback)` 注册工具
- 现有工具示例：`self.audio_speaker.set_volume`、`self.light.set_rgb`、`self.get_device_status`、`self.camera.set_camera_flipped`
- 参数类型：布尔/整数/字符串

**对我们的用处**：
- 表情屏控制：可注册 `self.display.set_emotion`（开心/难过/惊讶），LLM 返回的 emotion 字段直接驱动
- 物理按钮：可注册"再讲一遍""换一个"等儿童高频操作的硬件键映射
- 家长控制：可注册 `self.parent.lock`（家长一键锁屏/静音），通过 MCP 下发

### 5.2 云端 MCP（MCP Client 跑在服务器上）
- 服务器作为 MCP Client，可接入外部 MCP Server 扩展 LLM 能力
- 官方示例：智能家居控制、PC 桌面操作、知识搜索、邮件收发
- **对我们的用处**：可把"查课程库""记成长事件""调 omemo 记忆"包装成 MCP 工具供 LLM 调用，比硬编码 prompt 更干净

## 七、延迟评估

- 服务器官方：流式配置比基础版响应快约 2.5 秒（原文 "~2.5秒" 提升）
- 服务器自带 `performance_tester.py` 可实测各组件耗时；另有 Web 端到端音频测试页
- 第三方实测参考：本地 LLM 热态首 token 可 <0.1 秒；TTS 首句合成 1-3 秒；主要延迟来自网络 + 模型冷启动
- **儿童场景要求 5 秒内回复**：流式 ASR + 流式 LLM + 流式 TTS（首句即播）理论上可达标，**但必须实机实测**，标注"待实测"

## 八、唤醒词

- 基于 ESP-SR（乐鑫离线语音框架，Apache 2.0），WakeNet 模型本地运行，不联网
- **支持自定义唤醒词**：官方 README 明确列出；需在编译时配置对应模型（`pack_model.py` 打包 + 烧入 model 分区）
- 孩子起的名字（如"小蛋糕"）可做唤醒词，但需注意：① 名字最好 3-4 个音节，太短误唤醒率高；② 需重新编译烧录固件，不能 OTA 换词
- 备选：先用默认"你好小智"验证全链路，名字定下来后再编译定制固件

## 九、儿童适用性：内容安全

**现状（空白）**：
- 固件端：无家长控制、无内容过滤、无使用时长限制
- 服务器端：无敏感词过滤、无话题限制；记忆/声纹等功能是通用设计
- 官方 xiaozhi.me 服务器：通用 LLM，无儿童模式（控制台可设人设，但那是 prompt 层，无强制约束）

**我们的补齐方案**（自建服务器时做）：
1. system prompt 注入儿童教育宪章 v2.0（已有）
2. 输出过滤中间件：敏感词 + 不适宜话题拦截（新增开发）
3. 声纹区分孩子/家长：家长语音可解锁"家长模式"（查成长报告、改设置）
4. 使用时长统计：服务器端记录每日对话时长，超限提醒（新增开发）
5. **红线**：麦克风数据只存于自建服务器，不上传第三方；对外承诺"不出家门"
